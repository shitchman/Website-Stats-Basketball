# 2K React App

## Development Startup

Run these commands from the `Frontend` folder:

```powershell
cd Frontend
```

Install frontend dependencies once:

```powershell
npm install
```

Install backend dependencies in the project virtual environment once:

```powershell
..\.venv\Scripts\python.exe -m pip install -r ..\Backend\requirements.txt
```

Open two terminals in the `Frontend` folder and run:

```powershell
npm run backend:dev
```

```powershell
npm run dev
```

Open `http://localhost:5173`. The API runs at `http://localhost:8000`.

## Production Deployment

The application uses Supabase as hosted PostgreSQL through FastAPI. The browser does not access the database directly: React calls FastAPI, and FastAPI connects to Supabase using `DATABASE_URL`. This keeps the database password out of the frontend.

The production services are:

- Supabase: hosted PostgreSQL.
- Render: Dockerized FastAPI API, including Tesseract for OCR.
- GitHub Pages: static Vite/React frontend over HTTPS.

### Deploy FastAPI to Render

1. Push this repository to GitHub, then create a Render **Blueprint** from it and set the Blueprint path to `Backend/render.yaml`. The Blueprint configures the Dockerfile, repository-root build context, health check, and runtime environment.
2. During Blueprint creation, provide these values when Render prompts for them:

```dotenv
DATABASE_URL=postgresql+psycopg://postgres.PROJECT_REF:URL_ENCODED_PASSWORD@aws-0-REGION.pooler.supabase.com:5432/postgres?sslmode=require
```

Use the Supabase **Connect > Session pooler** URI for `DATABASE_URL` and URL-encode special characters in its password. Render generates `SECRET_KEY`; `ENVIRONMENT=production` and `CORS_ORIGINS=https://shitchman.github.io` are fixed in the Blueprint. If configuring a Web Service manually instead, use `Backend/Dockerfile` with the repository root as its Docker build context and set all four variables from `Backend/.env.example`.

3. The deployed API is available at `https://twok-stats-website.onrender.com`.

### Deploy React to GitHub Pages

1. The Pages workflow configures the public API URL as:

```dotenv
VITE_API_BASE_URL=https://twok-stats-website.onrender.com
```

2. Open **Settings > Pages** and choose **GitHub Actions** as the source.
3. Push to `main`. The `Deploy frontend to GitHub Pages` workflow builds `Frontend` and publishes `Frontend/dist`.
4. Open `https://shitchman.github.io/Website-Stats-Basketball/` and confirm GitHub Pages reports that HTTPS is enforced. For a custom domain, configure its DNS in **Settings > Pages**, wait for the certificate, and enable **Enforce HTTPS**.
5. The Render Blueprint allows the exact Pages origin, `https://shitchman.github.io`. The repository path is intentionally omitted because it is not part of a CORS origin.

Production builds reject missing or non-HTTPS API URLs. `ENVIRONMENT=production` enables `Secure; SameSite=None; HttpOnly` authentication cookies for the cross-site API. Never place `DATABASE_URL` or `SECRET_KEY` in a frontend variable or GitHub Pages artifact; every `VITE_` value is public in the browser bundle.

Render's filesystem is ephemeral unless a persistent disk is attached. Database records remain in Supabase, but uploaded OCR image files can disappear after a restart or redeploy. Attach a disk at `/app/app/storage` on a compatible Render plan, or move image persistence to Supabase Storage before relying on those files long-term.

Before deploying the API, apply the Supabase migrations as described in [supabase/README.md](supabase/README.md). Production startup does not create or alter tables.

Python bytecode generated by the backend is redirected to the project-level `.pycache` folder via `PYTHONPYCACHEPREFIX`, so `__pycache__` folders do not spread through the source tree. Existing `__pycache__` folders can be deleted once the backend is stopped.
